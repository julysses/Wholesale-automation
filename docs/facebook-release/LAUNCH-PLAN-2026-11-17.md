## Website Turnstile release checklist

- [x] Guard Hilltop offer forms on the homepage and `/get-an-offer`, all Jays funnels at `/sell`, `/contact`, `/buyers` and `/financing`, and the corresponding protected WholesaleOS-hosted forms. The common API checks the provider verdict, hostname and form action before creating a receipt or doing follow-up. The challenge token travels with only the current request and stays out of the durable draft and receipt. Retries obtain a fresh token and keep the original inquiry reference.
- [ ] **Cloudflare/hosting owner with Codex** creates the managed widget and binds the approved site hostnames, including the WholesaleOS public form host. Use a distinct widget for local or preview testing and route previews to an isolated CRM environment. Cloudflare dummy keys can test ordinary widget flows, and strict hostname/action checks need real environment keys or controlled fixtures. [Cloudflare testing](https://developers.cloudflare.com/turnstile/troubleshooting/testing/)
- [ ] **Codex** configures `NEXT_PUBLIC_WEBSITE_TURNSTILE_SITE_KEY` on the Hilltop and Jays site builds. Configure `WEBSITE_TURNSTILE_SITE_KEY` and `WEBSITE_TURNSTILE_SECRET` on the CRM backend. Keep the secret in hosting settings. Stage the CRM code with `WEBSITE_TURNSTILE_REQUIRED=false`, ship the two branded website clients and verify that each receives the widget. Promote the reviewed CRM build with `WEBSITE_TURNSTILE_REQUIRED=true` once compatible clients are serving. The website release needs no database migration. [Turnstile server validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- [ ] **Codex** verifies a real allowed-domain response on desktop and mobile for both sites and checks every funnel. Confirm signed-off test inquiries produce the same receipt, lead, task and owner alert. In isolated or approved checks, verify missing, invalid, expired, repeated and wrong-site tokens stop before any write and provider outages show a retry. Verify direct CRM submission by slug and UUID obeys the same check and survey any alternate production backend before declaring coverage complete.
- [ ] **Codex with Julio** compares legitimate intake and spam for the first 48 hours. If legitimate submissions break, restore the known-good CRM intake setting or deployment, verify both sites can take inquiries and track the window when spam checks are off while correcting widget configuration. Keep a note of the before/after accepted and rejected counts without storing raw challenge tokens or inquiry details in Git.
